# Automatic C/C++ navigation index — contract freeze request

Status: design approved; Unit A accepted at 2c5d007 and Unit B implementation authorized on that commit by plan-control, 2026-11-09. Review baseline for the overall feature remains fd7d612. Numeric policy SSOT is plugins/common/tools/lsp_index_policy.py; it is a product proposal derived from evidence and delegated decisions, not a rewrite of the immutable experiment policies.

## Goal and alternatives

Automatically make trusted clangd definition/references useful beyond the opened translation unit. No enabling flag, daemon, install, new model evaluation or token/speed promise. Preserve host-native LSP priority. Keep the accepted 5.7.2 honesty patch separate from the expected 5.8 minor.

Chosen time design: first qualifying empty key gets the longer total budget, existing/attempted keys the short budget. All invocation work, lock wait, initialize, initial partial query, readiness, coverage, final query and cleanup share the original monotonic absolute deadline. Initial validated data is retained when available. If no response was validated before interruption, do not invent an empty no-match: retain the existing error/unverified rc2 contract without a success result.

Rejected alternatives: perpetual short calls do not finish the measured medium STL fixture in the bounded task retry window; unbounded identical retries obscure task latency. A daemon was unnecessary for correctness/reuse in the native measurements and adds lifecycle/memory costs.

## Journey and states

1. Existing source validation, executable trust/pinning/argv0, PATH filtering and filtered toolchain environment apply. Only normal C/C++ definition/references, default known clangd arguments and supported POSIX platforms enter automatic indexing. Custom arguments remain partial, regardless of an index-looking flag. symbols/diagnostics/other languages retain contracts.
2. HIWAY_CODE_INTEL_INDEX=0 goes directly to the existing partial path without cache writes. Missing/safely unsupported CDB, effective config, cache, monitor or platform likewise retain valid partial results and a fixed reason. A native server is trusted code, not an OS sandbox; arbitrary project plugins/servers can still execute code and write files. The helper's cache/CDB/tmp mechanism writes outside source; tests prove source invariance for supported authored fixtures, not confinement of arbitrary trusted code.
Indexed server argv is fixed (no other appended args): `pinned clangd --background-index --limit-references=0 -j 2 --enable-config=false --compile-commands-dir=<frozen copy> --log=error`. The non-indexed partial path retains fd7d612 argv. The default target no longer uses --background-index=false; custom/unsupported fallbacks still do.

3. Discover/read supported CDB and enumerate effective config presence before allocating an index. Acquire the global scheduler lock then key lock in one order, with a bounded wait. Waiting past the bound returns partial lock_timeout; no second indexed server starts. The global lease lasts through process exit, coverage/metadata finalization and cleanup, so only one extra indexed server per user-cache is live.
4. Classify the locked key. New means zero valid persisted shards AND no durable attempt-consumed marker. Atomically consume the first long-budget grant before indexed startup. A timeout that leaves shards is existing; a startup failure/timeout that leaves zero shards is also attempted/existing. This closes the zero-shard loophole in 'no repeated long budget'. Concurrent losers do not consume/grant another long budget. Explicit safe LRU deletion permits a genuinely new key later; disclose reindex cost.
5. Initialize/didOpen with progress capability, obtain/validate initial navigation if time allows, then wait for the actual backgroundIndexProgress begin/end token. Progress-end alone is insufficient. Silence, an unrelated token or a malformed sequence is not readiness. No golden waiting or quiet-time inference.
6. Read bounded metadata from exact TU shards while the process/lease is controlled, require coverage predicates below, then issue a final request and validate the full response. Emit complete:true only for observed readiness + verified current scope/coverage + full validated native response within all budgets. Then bounded shutdown/exit/close/wait/kill leaves zero children.

State precedence: a confirmed protocol/schema/security/input failure does not become success because there was a progress end. Disabling/unavailable/custom/no-CDB/config paths are partial. Index timeout/memory/cache/coverage/errors/input-change retain the latest validated partial if available. Do not clip a final response or silently drop TU entries while marking it complete.

## Supported inputs, trust and invalidation

Read CDBs from the active file's ancestors **within the explicit workspace**, checking the native root/build convention nearest-first; never widen the workspace to a repository ancestor. Use one selected frozen external CDB copy and --compile-commands-dir. Only regular safely pinned inputs are accepted; a CDB symlink may resolve once to a contained workspace regular file, then access uses anchored FDs/no-follow, never repeated resolve. Escapes/loops/ownership/read errors are partial. Each entry's file/directory must resolve within the explicit workspace and be represented without lossy clipping; unsupported entries make the whole CDB unverified. Parse JSON strictly, support native command/arguments input, never execute its command string. Response-file arguments are unsupported in this release because CDB bytes do not cover their changing contents. Compiler argv0 must be an absolute path; bare/relative names can resolve through PATH/xcrun and change standard-header semantics. This narrows support to the absolute compiler form used by the measured generated CDBs; generated CMake-style databases commonly use it, but do not assume every generator does. Response files, bare compilers and out-of-scope/unsupported CDB entries use compile_db_unsupported, distinct from missing CDB and config_unsupported. No rewriting/guessing a compiler command merely to make it qualify. CDB size/entry/depth limits are policy, not inferred native limits.

Config choice **(ii), agreed after native External contamination**: enumerate .clangd along all ancestors of queried file and CDB TUs, including ancestors above the workspace for presence detection, plus OS-specific effective user config (macOS HOME/Library/Preferences/clangd/config.yaml; Linux XDG_CONFIG_HOME/clangd/config.yaml or HOME/.config/clangd/config.yaml). Presence/unknown/read error means config_unsupported and no index allocation. Do not hand-parse YAML. Existing partial server keeps user config semantics. Only proven absence allows --enable-config=false on the indexed server; recheck inventory before returning, and downgrade if it changed. compile_flags.txt absence is required along supported discovery chains, even though CDB beat flags in the control, avoiding an unenumerated fallback input. This deliberately limits coverage for configured projects; disclose it rather than silently disabling their settings. Support for semantic configs/response files can expand separately with evidence.

Key inputs: schema/rule version, original CDB bytes, canonical CDB path and canonical TU paths (neither TU nor CDB inodes enter the key; CDB stamps only detect in-call changes; B-R2 correction), canonical workspace path/identity, pinned actual clangd binary identity/version, the CDB absolute compiler identities, resolved default macOS SDK path, supported effective config-absence inventory and only the semantic environment names in plugins/common/tools/lsp_index_policy.py (hash values, never expose them). The exact environment list is CPATH, C_INCLUDE_PATH, CPLUS_INCLUDE_PATH, SDKROOT and DEVELOPER_DIR, and only values actually forwarded by the existing filter participate (absence and empty are distinct). Native CPATH off/on controls and SDKROOT command evidence support keying them; Clang documentation identifies C/C++ include environment semantics, and pinned macOS tool/SDK selection identifies DEVELOPER_DIR relevance. Do not add OBJC_*, TOOLCHAINS or deployment variables not currently forwarded, and do not modify the shared environment filter in this feature. PATH is replaced by pinned tool/compiler identities; temporary paths, XDG runtime/cache locations, shell/user/locale, VIRTUAL_ENV, CONDA/CARGO/RUSTUP/Go namespaces do not fragment the semantic key. Cache-root selection and config inventory still use their effective paths but session storage values are not hashed as parsing semantics. Resolve the macOS xcrun trampoline once to the actual trusted native executable before versioning/launch, using the same trust/pinning rules and shared budget; failure is unavailable. No query-driver/custom plugin flags are added. Source/header content changes rely on native digest revalidation and get separate real controls; do not hash only the opened file or treat a key/manifest as readiness.

## Coverage proof and limits

The observed Apple engine generated RIFF/CdIx metadata version in the policy allowlist. Upstream source explains fields, but Apple equality was verified on actual shards. Do not add a clangd-version-to-schema guess. Unknown format/chunks, bounded-decompression failure, unreadable, empty, truncated or unsafe shard means index_coverage_unverified.

Read shard metadata with stdlib struct/zlib using size caps, strict RIFF/chunk lengths, no duplicate/unknown chunks, bounded max_length decompression/eof checks, bounded strings/varints and known flags. Required metadata/source graph/command chunks must validate. Associate each CDB TU using its exact decoded local URI, IsTU flag and command source argument under the **same path/identity function as CDB input**. Candidate basename is a lookup optimization, never proof. Filesystem identity handles macOS case aliases; two different same-named TUs remain distinct. HadErrors anywhere in the TU source graph produces index_had_errors. CDB duplicate configurations for one TU require an explicit single canonical scope or fall back; do not count a basename twice as proof.

No xxh3 dependency/reimplementation is added to predict opaque filenames. This URI/metadata route is stronger than basename counts and handles same-name TUs, at the cost of a bounded internal-format reader. Exact filename-digest calculation would still need metadata validation and a new hash implementation. The reader certifies coverage metadata, **not symbol/ref body correctness**: clangd's load/rebuild and validated response remain responsible for those internals. Unknown schemas safely degrade to partial after an upgrade. No claim of perfect C++ semantics, successful builds, every repository file, alternate compile configurations or arbitrary plugins.

## Cache, monitor and cleanup

Use XDG_CACHE_HOME/hiway-kit/code-intel/clangd, otherwise HOME/.cache/hiway-kit/code-intel/clangd; reject relative, workspace/plugin-contained, unsafe shared/writeable or linked roots. User-owned private directories, non-followed locked anchors, atomic metadata/CDB writes, file identity checks, strict key names and safe FD-relative deletion are unit A requirements. Put transient preambles/tmp under the owned key and include them in sizes; cleanup after native exit. B-R2 separates temporary space into a 512 MiB sampled target; overflow retains persistent shards. Clear leftovers before starting another attempt. Neither the helper's plugin directory nor consumer source is its cache.

Both key and aggregate retained usage are cleanup/watchdog targets, **not physical hard disk quotas**. Native writes can overshoot between samples and RSS peaks can be missed; publicly disclose this. Before starting, make room under the retained-byte/key policy using LRU, skip active entries, never delete locks to break contention. If cleanup cannot safely meet targets, return cache_limit. During native writes sample disk/RSS, stop on limits, remove an unsafe/over-budget key after native exit, preserve bounded failure evidence, and never return complete. Native .cache layout and fallback writes in the controlled environment are checked by integration tests.

macOS: libproc child-tree sampling with failures explicit. Linux: bounded /proc descendant/stat/statm or status sampling, with PID identity/race handling; no setuid ps dependency. Failure/unknown RSS, owner/lock/no-follow support is index_unavailable, not an unlimited run. Mandatory Ubuntu fake contracts plus real /proc self/child, flock contention and no-follow/ownership tests close portability at implementation validation. Python3.9 runs actual coordinator/parser/CLI contracts. Unsupported platforms do not try indexed spawn/cache allocation. Local macOS proof does not close CI acceptance.

## Output and retry contract

Keep status/complete/action/server/file/result behavior. Add fixed reason + human message for partial navigation, and metadata: scope=selected_compile_database, input TU count, covered TU count, persisted shard before/after (distinct from TU count), cache path/key hit/created/attempted classification, selected total deadline, readiness, and filtering notice. Never echo configuration or environment contents; hash inputs only. Progress count is not a completion percentage: headers produce shards too.

Reasons: index_disabled, no_compile_db, compile_db_unsupported, config_unsupported, index_unavailable, index_deadline, lock_timeout, cache_limit, index_resource_limit, index_coverage_unverified, index_had_errors, index_inputs_changed; project_index_not_verified remains for uncertifiable custom paths. Error branches keep errors; rc0 is complete navigation, rc2 is valid partial/unverified/error as documented, rc3 retains unavailable-tool contracts. The administrative disable/cache-unavailable still return existing valid data when server query succeeds.

SKILL gets one interpretation: partial data is useful and is not absence proof. An identical query may be retried only for index_deadline with strictly increased valid persisted progress, up to the policy's additional-attempt bound. No internal automatic loop. Other reasons/stalled progress use grep/build/native-host tools. First use can block for the longer budget; very large projects can remain partial over multiple tasks, and LRU removal can repeat that cold cost. README/SKILL disclose paths, deletion (only when no indexed query is running), caps/overshoot, concurrency, opt-out, config/format limitations and no daemon.

Large design approval precedes product code. Unit A: new coordinator/cache/coverage/resource modules + focused tests, independently reviewed. Unit B: lsp_transport/lsp_query integration and CLI contracts, separately reviewed after A. One unpublished minor behavior commit with scripts/bump-version.sh avoids artificial intermediate tags; docs/spec and docs/plans are then copied into the reviewed implementation tree.

Nodes must prove new/attempted deadlines including zero shards, lock losers, safe LRU, denied writes/no-source changes, unknown platform/monitor failure, matching URI identities, corrupted/unknown schema/bombs, HadErrors, withheld end, config appearance/CDB/env change, two calls differing only in PATH/TMPDIR/CONDA_*/SHELL sharing one key hit, CPATH/SDKROOT changes producing new keys, bare compiler/response-file unsupported reasons, custom args/disable/no-CDB, result-limit removal, valid partial retention, zero leftovers and unchanged non-target actions. Run fake contracts in Ubuntu and real Python3.9 runtime locally/CI, not import smoke alone. Production reversion must FAIL the new contract suites.

Optional native controls are separately labeled with installation/skip reasons: normal and same-name cross-TU references, other-TU definition, source/header edits, CDB/env invalidation, scoped readiness, controlled cache/no-source writes, and D1 persisted progress evidence. Existing step1/Phase0 data supports design; frozen implementation must rerun appropriate integration controls. Fresh scripts/verify-done.sh rc0 on the frozen implementation + independent ACCEPT + behavior-eval scope evidence/waiver + Ubuntu + directory Validate-only are release conditions. No main/tag push under the v5.7.1 gate; plan-control owns publishing.

C1/C2 primary clarification: [clangd compile-command design](https://clangd.llvm.org/design/compile-commands#tweaks-always-applied) documents PATH/xcrun compiler and SDK inference; [Clang environment](https://clang.llvm.org/docs/CommandGuide/clang.html#environment) documents include-search variables. This design avoids adding unrelated per-session state to a reusable cache key while preserving supported compilation semantics.
