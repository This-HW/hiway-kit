# 하네스 중립 협업·자원 생명주기 정비

## Goal
공통 규범과 환경별 실행을 분리하고 통합 권한·종료 후 자원 처리의 모순을 제거한다.

## 승인 및 요구사항
2026-09-14 대화에서 사용자가 다섯 위치의 정비를 승인했다. 운송 문서는 외부 오케스트레이션, 네이티브 subagent, 대규모 병렬, 단일 세션 경로를 유지한다. 특정 모델·하네스에 편중하지 않는다.

## 접근 방식 및 구조
- 공통 규범: 수정 작업자 격리, 읽기 전용 비격리, disjoint 파일 소유권, 검증된 산출물 반환, 지정된 통합 담당자의 병합.
- control-loop: 부모의 계획·배정·검증·통합, 실제 자원 목록 조회, 재사용/사용자 요청 보존/해제/차단의 증거 보고.
- definition-of-done: 위임 시 산출물 보존과 자원 처리 확인을 수동 attest에 연결. 상세 절차는 control-loop가 소유한다.
- 운송 문서: 하네스와 오케스트레이터를 별개 축으로 설명. 설치된 가이드·capability·실행 영수증을 확인하고 지정된 수단을 묵시적으로 대체하지 않는다.
- 프로젝트 선택: AGENTS/GEMINI/CLAUDE가 공통 프로젝트 운영 문서를 참조한다. 개인 모델 선호는 배포 규범 밖에 둔다.

## 사용자 여정·상태·오류
부모가 수단과 소유권을 확정 → 작업자가 격리/읽기 전용으로 작업 → 보고·diff·검증 확인 → 담당자 통합 검증 → 자원 처리.
빈 응답/연결 단절은 종료 증거가 아니다. 미확인 상태는 보존하고 차단 사유를 보고한다. 터미널 해제와 워크트리 삭제를 분리한다. 미병합 커밋·수정/미추적/ignored 파일 보존을 확인한 뒤 소유 범위만 정리한다. hooks trust·보안 게이트를 우회하지 않는다.

## 검증
기존 예산·규칙 checksum·미러·하네스 생성·이름/매니페스트 검사와 전체 verify-done을 실행한다. 독립 문서/안전성 리뷰로 성공·실패·읽기 전용·연결 단절·명시 수단 부재 경로를 대조한다. 실제 worker 시작/종료 확인은 그 실행 범위만 증거로 기록한다.

## 범위 외
개인 Codex 설정/모델 버전 별칭 변경, 자동 삭제 기능, 새 검사 프레임워크, 기존 W-023 배포 재개, 외부 게시. 새 모델이나 다른 하네스의 실행 성공을 문서만으로 주장하지 않는다.
