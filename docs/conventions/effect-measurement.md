# 효과 측정 규약 — 규칙·훅·스킬이 결과를 바꾼다고 말하려면

이 레포는 **정확성**은 잘 잰다. 게이트는 문서가 가리키는 파일이 있는지, 훅이 3.9 에서 로드되는지,
에이전트 출력이 계약을 지키는지를 exit code 로 판정한다. 그런데 **효과**는 재지 않는다 — 매 세션
주입하는 규칙, Stop 훅의 자동 수정 루프, 스킬의 한 절이 *결과를 좋게 하는가* 는 측정된 적이 없다.
그래서 이 문서는 효과를 **주장하려는 사람**에게 절차를 요구한다. 측정을 의무로 만드는 문서가 아니다.

**이 규약이 도는 조건** (`warning-signal.md` §검토 4): CHANGELOG·README·`docs/`·스킬·사이트에
*"X 가 결과를 개선한다·줄인다·막는다"* 류의 **효과 문장**을 쓰려 할 때. 그때 아래 절차의 결과가
없으면 그 문장을 쓰지 않는다(`release-process.md` 의 발행 직전 체크가 이 문서를 가리킨다).
정확성 문장(*"protect-sensitive 는 `.env` 경로를 막는다"* — 테스트가 증명)은 대상이 아니다.

## 실행 전에 커밋한다 (사전등록)

측정을 돌리기 **전에** 아래를 레포에 커밋한다. 커밋 해시가 사전등록의 증거다 — 결과를 본 뒤 고친
흔적이 git 에 남는다.

| 항목 | 적을 것 |
| --- | --- |
| 가설 | 한 문장. *"`on` 팔이 `off` 팔보다 함정 과제를 더 많이 통과한다"* |
| 주결과 | **하나.** 주장을 가르는 것은 이것뿐이다. 나머지(턴·질문 횟수 등)는 보조이며 주장을 지지하지 못한다 |
| 검정 | 쌍대 설계면 **양측 exact McNemar**, 유의수준(예: 0.05) |
| 표본 수 | 시나리오 × 반복 = 쌍 수. 어떤 효과 크기를 몇 % 검정력으로 보려는지와 그 근거 |
| 중단 규칙 | 표본을 다 채우면 끝. 무효 시행(공급자 오류·타임아웃) 처리와, 무효가 몇 % 를 넘으면 "판정 불가"로 보고하는지 |
| 고정 입력 | 시나리오·채점기·프롬프트·팔·모델을 고정한 커밋. 실행 중 추가·삭제·수정 없음 |
| 비용 예상 | 시행 수 × 시행당 비용. API 비용이 들면 실행 전에 사용자 승인 |

## 팔(arm)

- **`off` 팔은 필수다.** 비교 대상 없는 "on 에서 잘 됐다" 는 효과가 아니라 기술(記述)이다.
- 개입이 **멈춤** 자체로 효과를 낼 수 있으면(질문·차단·재시도) **placebo 팔**을 둔다 — 같은 지점에서
  같은 횟수로 멈추되 내용은 일반적인 것. 이게 없으면 *"무엇을 물었나"* 와 *"멈췄다"* 를 가를 수 없다.
- 같은 시나리오·반복을 팔끼리 **쌍**으로 묶는다(같은 시드·같은 입력). 그래야 McNemar 가 성립한다.

## 결과를 읽는 규칙

- **연장·단축·재실행 금지.** 결과를 본 뒤 표본을 늘리거나 줄이지 않는다(optional stopping). 아슬아슬하게
  못 미친 결과는 *못 미친 결과*로 남는다. 다른 설계로 다시 재려면 **새 사전등록**을 커밋하고, 두 실행을
  합산하지 않는다 — 결과를 보고 합칠지 정하는 것이 사전등록이 막으려는 사후 선택이다.
- **귀무도 보고한다.** 유의하지 않으면 *"효과 없음"* 이 아니라 **"미확립"** 이라고 쓴다. 효과 크기 추정치와
  그 크기를 확인하려면 몇 쌍이 필요한지를 같이 적는다.
- **비용을 효과 옆에 적는다.** 턴 수·토큰·지출은 팔마다, 같은 쌍대 비교로. 비용은 대개 효과보다 훨씬
  안정적으로 재진다 — 효과가 미확립이고 비용이 확실하면 그 자체가 판단 근거다.
- **기제 관찰은 주장이 아니다.** *"정답 사실을 얻은 시행만 통과했다"* 같은 연관은 시나리오 단위 관찰
  자료다. 필요조건·인과 매개를 확립하지 않는다.

## 설계 함정 — 실험이 **구성상** 정보를 못 내는 경우

아래 둘은 ECC(`affaan-m/ECC`)가 자기 질문 게이트의 효과를 재다가 공개적으로 밟은 것이다
(출처: ECC 저장소의 docs/gateguard/question-effectiveness.md "Pilot results"·"Why it measured nothing" 절과
ECC CHANGELOG 의 Unreleased 항목 — 이 레포 밖의 자료이며 우리가 재현한 것이 아니다 `[외부 보고 n=1]`).

1. **결정 사실이 레포 안에 있으면 모든 팔이 천장에 붙는다.** ECC 의 파일럿은 6 시나리오 × 4 팔 ×
   3 반복 = 72 세션이었고 **모든 팔이 모든 시행을 통과**했다(McNemar p = 1). 함정을 푸는 사실이 전부
   저장소 안에 있었고, 에이전트는 저장소 사실을 잘 찾는다 — 그래서 개입이 도울 여지가 없는 곳에서
   잰 셈이 됐다. 질문 채널도 꺼져 있었다("질문하지 말고 자율로 작업하라"). 결과는 *효과 없음의 약한
   증거* 가 아니라 **측정의 부재**였다. 남은 것은 비용(턴 약 45% 증가)뿐이었다.
   → 시나리오를 쓸 때 묻는다: *"개입 없이도 레포를 읽으면 풀리는가?"* 그렇다면 `off` 팔이 천장이다.
   결정 사실은 레포가 답할 수 없는 곳(시뮬레이션된 사용자의 숨은 의도 등)에 둔다.
2. **성공 기준이 개입의 어휘를 참조하면 구성상 통과한다.** ECC 의 시나리오는 *"게이트가 이 질문 중
   하나를 묻는가"* 를 단언했는데, 그 질문 목록을 게이트 자신의 질문 분류에서 골랐다. 단언은 정의상
   참이었고, 시나리오 집합도 기존 질문 6개를 중심으로 만들어져 **빠진 질문을 발견할 수 없었다.**
   → 채점기는 **결과**(산출물이 정책을 따르는가)를 보게 하고, 개입이 쓰는 단어·규칙 ID·게이트 출력
   문구를 성공 조건에 넣지 않는다. 이 레포로 옮기면: `verify-done.sh` 의 섹션 이름이나 규칙 파일의
   문구가 채점 조건에 들어가면 그 실험은 규칙이 존재한다는 사실만 잰다.

같은 계열로 하나 더 — **시나리오 저자 = 개입 저자** 편향. 개입을 쓴 사람이 시나리오를 쓰면 개입이
다루는 경우만 고른다. 가능하면 개입을 보지 않은 사람(또는 세션)이 시나리오를 쓴다. 못 하면 그 한계를
결과에 적는다.

## 이 레포에서의 위치

- **규약만 있다.** off/on 팔을 돌리는 하네스는 아직 없다(`evals/run.py` 는 단일 팔 정확성 eval).
  하네스를 만들거나 돌리는 일은 API 비용이 들어 사용자 예산 승인 뒤의 별도 결정이다.
- 하네스가 생기면 이 레포 전용 도구로 둔다 — 배포물(`plugins/`)에 넣지 않는다(consumer-first).
- 비결정적이라 per-commit 게이트(`verify-done.sh`)가 될 수 없다. 릴리스 전 수동 실행이다.
- 측정 일반의 함정(양성 대조, 도달 증명, 같은 것을 셌는가)은 `warning-signal.md` §측정이 소유한다 —
  이 문서는 그중 **효과 주장**에 특화된 절차다.
